# 城市边界开发原型说明

## 当前范围

组件会根据当前旅行地点的稳定 cityId，从本地提取的市级边界中按需加载可用范围。运行时不会加载完整的全国市级文件。当前已提取并配置的 adcode 包括：

440100、440300、510100、330100、320100、420100、610100、430100、350200、530100、530700、460200、540100、230100、370200、450300、320500、520100、650100、150700、360100。

北京、上海、重庆、大理、西双版纳等候选地点在当前本地文件中没有可直接匹配的市级要素，因此不会伪造范围，也不会显示不存在的边界。新增地点的中文 ID 会通过配置中的城市名别名映射到同一份本地边界。

## 数据状态

- 来源记录：DataV.GeoAtlas / AMap（项目原有 DataV API 数据）
- 使用状态：development-prototype
- 坐标系：未确认，疑似 GCJ-02
- productionReady：false
- 当前 GeoJSON 文件没有明确 crs 字段
- 本数据仅用于本地开发、视觉和性能验证，不代表官方行政区划发布

本阶段不对坐标做自动转换，不人为添加经纬度偏移，也不把该数据描述为已确认的 WGS84 或可直接用于正式生产环境的数据。

## 开发保护

只有在开发环境并且设置 VITE_ENABLE_PROVISIONAL_CITY_BOUNDARIES=true 时，组件才会动态加载当前地点对应的边界。生产构建默认关闭。设置 VITE_SHOW_CITY_BOUNDARY_ALIGNMENT_DEBUG=true 时，悬停或选择城市会显示高对比度调试范围，并在页面左下角输出不含完整几何坐标的诊断状态。

批量提取可以使用：

npm run extract:city-boundaries

## 生命周期

城市范围统一放在独立的 CustomDataSource('city-area-glow') 中。默认边界实体会在城市数据源中保持，悬停离开只回到默认样式，不删除实体；页面卸载时才清理该数据源。城市标记使用 city-marker:<cityId> 命名空间，与范围实体完全隔离。

## 正式部署前

正式公开部署前需要确认数据许可和署名要求，并确认或转换为适合 Cesium 的坐标系。当前数据不用于导航、测绘或精确空间分析；如果与 ArcGIS 影像出现整体偏移，应先记录并核实来源，不凭视觉添加补偿坐标。
